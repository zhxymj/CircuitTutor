# 智绘电路企业命题报告 LaTeX 重构设计

## 1. 目标与定位

本次工作将现有《报告书.pdf》重构为面向中兴通讯“AI 辅助硬件设计”企业命题的正式技术解决方案。报告采用企业技术论文体例，以“AI 辅助原理图生成与工程验证闭环”为主线，以 PCB 智能布局探索为辅助方向，重点证明方案的工程可落地性、结果可验证性和证据可追溯性。

报告不制作 PPT 或视频，不改变项目程序的 API 配置，不在正文中暴露 API Key，不将尚未完成的实验或规划描述为既有成果。

## 2. 成功标准

最终报告必须同时满足以下要求：

1. 逐项回应企业命题中的场景聚焦、数据基础、技术融合、可扩展性、实验验证和实际价值要求。
2. 所有完成状态、规模指标和实验数字均可追溯到当前项目代码、测试输出或 `evidence/` 下的机器可读证据。
3. 清楚区分正式能力、实验性能力和未来规划，PCB 强化学习方向不得包装为已成熟落地的能力。
4. 提供从自然语言需求到 CircuitJSON、规则检查、确定性修复、KiCad 生成、官方 ERC 和证据归档的完整闭环。
5. 采用规范 LaTeX 论文排版，正文预计 22–28 页，图表、公式、引用、目录、页眉页脚和附录编号一致。
6. 使用 TeX Live 与 XeLaTeX 编译；最终 PDF 经过文本、元数据和逐页渲染检查，无乱码、溢出、重叠、空白页或不可读图表。

## 3. 交付物与文件边界

演示包根目录最终保留以下报告文件：

- `报告书-原稿备份.pdf`：开始改写前的原始 PDF，只创建一次，不重复覆盖。
- `报告书.tex`：新的完整、可编辑 LaTeX 源文件。
- `报告书.pdf`：由 `报告书.tex` 编译并验收后的正式交付 PDF，替换原正式版本。

编译产生的 `.aux`、`.log`、`.out`、`.toc`、`.xdv`、`.synctex.gz` 以及逐页 PNG 等文件放入临时目录，验收后不保留在演示包中。除非某项外部图像无法内嵌或用 TikZ/PGFPlots表达，否则不新增永久素材目录。

## 4. 信息源与证据优先级

报告事实按以下优先级确定：

1. 当前可执行代码和重新运行的测试结果；
2. `evidence/` 下与当前代码版本一致的 JSON、Markdown 和生成产物；
3. README、作品说明书、数据与实验说明等当前项目文档；
4. 原《报告书.pdf》中的历史叙述。

发生冲突时使用更高优先级证据。无法确认与当前版本一致的历史数字不得作为“当前结果”直接引用；必要时标注实验日期、模型别名、样本规模和适用条件。不得凭空补齐数据，不使用演示性截图代替可复核指标。

## 5. 内容架构

### 5.1 前置部分

- 中文封面；
- 中文摘要与关键词；
- 英文题名、摘要与关键词；
- 目录、图目录和表目录。

摘要采用“问题—方法—实验—结果—价值”结构，避免把功能列表写成研究贡献。

### 5.2 第一章：企业命题分析与问题定义

将企业需求拆分为具体、可验证的设计目标：减少原理图设计中的重复劳动，降低大模型输出直接进入 EDA 流程的风险，缩短从需求到可检查工程文件的路径，并形成可用于复盘和扩展的证据链。说明为何选择原理图设计作为主场景，以及其与通信设备研发流程的关系。

### 5.3 第二章：需求分析与总体方案

定义用户角色、典型工作流、功能需求、非功能需求和边界条件。给出系统分层架构：交互层、需求理解层、CircuitJSON 中间表示层、规则验证与修复层、KiCad 适配层、工程验证与证据层。每层说明职责、输入、输出和依赖。

### 5.4 第三章：关键方法

完整描述以下方法链路：

1. 自然语言硬件需求的约束提取；
2. 大模型候选 CircuitJSON 生成；
3. 元器件、引脚、网络、电源及设计规则校验；
4. 可证明、可重复的确定性自动修复；
5. KiCad 原理图生成、官方 ERC 和网络一致性检查；
6. 结果、日志、清单和证据的关联归档。

对可形式化的对象给出符号定义和指标公式，对关键流程给出算法或伪代码。大模型负责提出候选设计，确定性规则负责建立工程可信边界，两者的职责必须明确区分。

### 5.5 第四章：系统实现

按照当前代码结构说明前端或交互入口、模型接口、模板库、生成核心、规则检查器、自动修复器、KiCad 导出、测试和证据模块。仅描述当前存在且可验证的实现。说明在线模型不可用时现有离线或模板路径的作用，但不得把回退机制描述为模型能力。

### 5.6 第五章：实验设计与结果分析

实验部分至少覆盖：

- 固定合规样本集上的规则检测；
- AI 需求端到端生成；
- 模板到 KiCad 工程的批量生成；
- KiCad 官方 ERC；
- 网络一致性检查；
- 确定性自动修复；
- 项目回归测试和发布质量检查。

每项实验报告测试环境、版本、样本量、指标定义、结果、失败样本和限制。分类指标使用混淆矩阵并明确 TP、FP、FN、TN 的统计单位；效率指标同时报告总耗时和单样本耗时；成功率必须给出分子和分母。在线 AI 历史结果如未重跑，必须注明其历史属性、运行日期和模型别名。

### 5.7 第六章：消融分析与案例研究

使用项目已有证据比较“仅大模型候选”“加入 CircuitJSON”“加入规则检查”“加入确定性修复和官方 EDA 验证”四种链路的能力差异。如果现有证据不足以支持数值消融，则改为机制消融和受控案例，不虚构数据。

完整案例应从一条通信硬件需求开始，展示结构化约束、候选电路、发现的问题、修复动作、KiCad 产物和最终验证证据。

### 5.8 第七章：创新性、企业价值与可扩展性

创新点限定为项目实际实现：硬件语义中间表示、生成与验证解耦、确定性修复、EDA 官方工具复核、机器可读证据链。企业价值从研发效率、质量前移、知识复用和工具链集成四个方面论证。信号完整性、电源完整性、热设计和 PCB 强化学习只作为可扩展方向，并给出接口与验证前提。

### 5.9 第八章：局限性与结论

如实讨论样本规模、复杂电路覆盖、模型不确定性、规则库边界、官方 EDA 版本差异和 PCB 优化成熟度。结论只总结已被证据支持的成果，不引入正文未验证的新主张。

### 5.10 附录

- 企业命题要求与报告证据对照表；
- 指标定义与混淆矩阵口径；
- 关键 CircuitJSON 数据结构示例；
- 最小复现命令；
- 报告结论与证据文件映射；
- 版本与运行环境说明。

## 6. 图表与视觉规范

优先使用 LaTeX 原生 TikZ、PGFPlots、booktabs 和 longtable，避免低分辨率截图。核心图表包括系统分层架构图、端到端闭环流程图、证据链关系图、实验结果对比图、混淆矩阵、案例流程和命题要求追踪矩阵。

所有图表必须满足：正文先引用后出现；标题能够独立说明内容；坐标轴、单位、样本量和数据来源明确；颜色在灰度打印时仍可区分；正文不重复逐字抄写表格。

## 7. LaTeX 技术方案

- 文档类采用适合中文技术报告的 `ctexrep`；
- A4、11pt，设置统一页边距、段间距和约 1.35–1.5 倍行距；
- XeLaTeX 调用系统可用中文字体，提供稳定的字体回退；
- 使用 `hyperref` 生成可点击目录和 PDF 书签；
- 使用 `cleveref` 或等价机制统一交叉引用；
- 使用 `booktabs`、`tabularx`、`longtable` 处理表格；
- 使用 `tikz`、`pgfplots` 绘制矢量图；
- 参考文献采用可被当前 TeX Live 环境稳定编译的方案，并在交付前检查每个引用均有对应条目。

正文避免依赖 shell-escape 和联网下载，确保离线可编译。编译在临时构建目录执行，正式目录只复制 `.tex` 与最终 `.pdf`。

## 8. 验证策略

### 8.1 事实验证

- 重新统计版本号、组件类型数、模板数、规则检查器数和测试文件数；
- 重跑与报告结论直接相关且不依赖在线模型的测试与证据生成；
- 对历史在线模型结果核对原始摘要，不主动调用外部模型或消耗 API；
- 检查报告中的每个定量结论是否能映射到证据文件或命令输出。

### 8.2 LaTeX 验证

- 使用 TeX Live XeLaTeX 至少编译两轮；
- 检查未定义引用、缺失字体、溢出盒、重复标签和缺失资源；
- 使用 `pdfinfo` 检查页数、页面尺寸和元数据；
- 使用 `pdftotext` 检查正文可搜索性和中文字符；
- 使用 Poppler 将全部页面渲染为 PNG，逐页检查封面、目录、章节过渡、表格分页、图注、页眉页脚和参考文献；
- 修正发现的问题后重新编译并完成最终全页检查。

### 8.3 文件安全

创建备份前核对源文件与目标路径，若备份已经存在则保留，不静默覆盖。正式 PDF 仅在新版本编译和验收通过后替换。项目中的 API Key、环境变量和配置文件保持原状，报告中不输出其值。

## 9. 非目标

本次工作不包括：制作 PPT、录制视频、重新设计项目界面、上线部署、扩大在线模型调用、声称完成尚处于实验阶段的 PCB 强化学习能力、修改项目答案或业务逻辑。

## 10. 实施组织

经设计规范确认后，实施阶段分为三个可并行审查的专业任务：

1. 技术与架构专家核对代码结构、功能边界和方法描述；
2. 实验与证据专家重跑安全的离线验证并建立结论—证据映射；
3. 技术写作与 LaTeX 专家完成论文结构、图表和排版。

主代理负责整合、冲突裁决、统一事实口径、编译、逐页视觉验收和最终交付。
