## 本机 CircuitVision

在图片导入中选择“本机 CircuitVision”，提交图片后查看检测框、类别、置信度与 SAM2 mask。前端归一化为 PNG，调用真实 `POST /api/image/analyze`，`core/upstream_vision.py` 通过独立 Python 进程运行 `tools/circuitvision_worker.py`，worker 直接导入项目 `core/integrations/circuitvision/` 的检测和分割模块；固定上游源码仅作为来源证据，不从 `evidence/.../worktree` 加载 Python 实现。上游 YOLO、SAM2 transforms/refinement/wrapper 和推理函数的改编映射见模块内 `NOTICE`，Apache-2.0 LICENSE 原文已保留。

接口请求为 `{backend:"circuitvision", image:"data:image/png;base64,...", source_name:"图片名"}`。桥接单任务执行、限时 **180 秒**；错误分别报告 invalid_request/runtime_unavailable/busy/timeout/inference_failed，对应 HTTP 400/503/409/504/502。图像接口 JSON 上限10 MiB，PNG/JPEG 解码后最多2000万像素，前端沿用现有缩放流程。

成功结果仍为 `needs_manual_correction`、`circuit=null`、`accepted=false`、`electrical_validated=false`。器件类型、数值和每个引脚网络由用户明确确认；误检可显式排除，未知 IC 不静默丢弃。点击“补充漏检元件”可新增独立人工校正项，删除按钮只移除该补充项；即使原始检测为零，也可在明确填写器件类型、数值、全部有效引脚网络后生成候选。人工项记录 `added_manually=true`、`detection_index=null`，不追加或覆盖原始检测框；未知引脚（例如999）和缺失参数会阻止生成。完整候选复用 `/api/validate` 和现有审核、应用、编辑、撤销。原始模型结果、人工校正与门禁记录分别可查；取消、失败或陈旧响应不替换当前工程。

真实 CPU smoke 已在阻断 `src`、上游工作树和 third_party Python 模块导入的情况下读取上游固定 `circuits_1.jpg`：返回14个框与1280×720 mask，实际模块路径位于项目 `core/integrations/circuitvision/`。结果是单图运行合同，未标注识别真值。完整记录见 `circuitvision.json`（本地证据）；本轮CV独立增量（本地证据）5/5套件（22个Python测试及1套Node几何UI合同）通过；HTTP传输修复后另5/5复验，受控Edge合同最终8/8通过，原失败逐次保留。真实Edge＋server＋180秒bridge最终1/1通过：14框、mask前景26,685像素、HCD160线段/209点，`truncated=true`；页面显示蓝线、黄点和截断提示，原R900保持，未自动打开候选或调用validate。见真实浏览器证据（本地证据）、实际模型输入（本地证据）、界面截图（本地证据）。这只是实际单图调用链，不代表拓扑正确或电气接受。

## HCD 几何叠加

`core/integrations/hcd_topology.py` 从固定 HCD 源码移植6个函数：`estimate_eps`、`merge_points_adaptive`、`sample_line_connectivity`、`build_wire_cc_index`、`snap_point_to_cc`、`filter_noise_wires`。上游提交为 `5e5a957f41bdb60f4835fb7c887452a6dc469520`；源文件SHA与每项改编在 `HCD_NOTICE.md` 和 `source_manifest()` 中逐项对应。OpenCV HoughLinesP 与几何候选编排属于项目集成逻辑。

worker 将 SAM 前景 mask 和检测框传给 `compute_wire_geometry(mask, *, component_boxes=(), line_segments=None, max_segments=160)`。输出 `wire_geometry` 包含线段、点、像素域与歧义交叉点；主页面显示几何叠加。它不输出电气连接：`topology.status=not_inferred`，`connections/nets` 为空。交叉、桥接、断线、框内像素及未知引脚/地仍须人工确认；几何证据不能当作电气候选或门禁通过。

数值算法测试17/17通过，含负例、参数边界、截断与来源核对；既存单图mask用于几何 smoke，无需重复模型推理。见 `hcd.json`（本地证据）。HCD完整多阶段模型未运行，根许可证未明确、一个MMPose子模块缺内容；当前本地算法复用不改变这些事实。

## 代码建电路

主页面打开“代码建电路”，可载入 `tools/upstream_examples/tscircuit_rc.tsx` 的RC示例，编辑TSX后本机生成。`POST /api/design/tscircuit` 接收 `{code,name}`，由 `core/tscircuit_engine.py` 调用 `tools/tscircuit_worker.mjs`；worker 复用已安装的 `@tscircuit/eval` 0.0.1619、`@tscircuit/core` 0.0.2156 和 `circuit-to-svg` 0.0.450，生成真实 Circuit JSON 与SVG。`GET /api/design/tscircuit/example` 提供本项目示例。运行关闭 CDN 加载，使用现有本机npm环境。

tscircuit 的 Circuit JSON 与项目 CircuitJSON 是不同合同。实际生成结果经现有 `core.external_import` 转换后进入候选审核，继续真实 `/api/validate`、应用、编辑和撤销；尚未完成门禁的候选不声明电气通过。代码错误、缺运行环境、超时与无法完整映射的IC明确失败，保留可用诊断或预览，当前工程保持。具体HTTP合同和状态码见[API文档](API.md)。

第三方库复用与项目编排代码的区别、固定版本和许可证见 [`tscircuit-runtime-attribution.json`](../third_party/tscircuit-runtime-attribution.json)。eval/core 的 package.json 未声明license字段，但本机实际 LICENSE 正文均为MIT；完整性审查记录实际证据与SHA，未改造包元数据。真实本机后端8/8用例通过；真实Edge主页面3/3通过，核对RC预览、真实import门禁与审核应用、编辑保存后JSON值2kΩ、两次撤销以及错误/取消保图，原断言失败保留在previousRuns。RC样例实际2R＋1C、无电源被动网络，适用8项官方门禁通过；生成结果仍是needs_review，接受由后续审核与门禁决定。详见后端证据（本地证据）和真实浏览器证据（本地证据）。

## 教学时序图（wavedrom）

教学模式里的“瞬态时序图”由第三方渲染器 wavedrom 3.7.0 出图，数据来自本机 ngspice 的真实 `.tran` 输出。`core/spice_enhanced.py` 的 `transient_series()` 先跑一次 `.op` 取节点名，再拼出带 `.print tran v(...)` 控制卡的网表（批处理模式下 `.tran` 默认不打印波形，必须显式加该卡），运行后解析真实时间序列表；`POST /api/spice_transient` 返回 `ran / engine / reason / nodes / time / series / rows / point_count / deck`。前端 `web/workbench.js` 只做阈值数字化与排版：按各节点电压中值把模拟量折成 0/1，再把 WaveJSON 交给 `window.wavedrom.renderAny` 渲成 SVG。

该图有明确边界：只在教学模式开启时出现；ngspice 不可用、无电压节点或输出无法解析时返回 `ran=false` 并显示“未运行 + 原因”，**不生成示意波形，也不以解析解替代波形**；图上标注阈值、每格时长与 `.tran` 采样行数。阈值数字化会丢失模拟细节，此图用于教学阅读，不是实测波形，也不构成电气验收或制造结论。

来源与许可：仓库 https://github.com/wavedrom/wavedrom，发布包 `wavedrom@3.7.0`（npm tarball shasum `50e4b3a833d55b40b18224a72713abb5593d0918`），MIT。本项目只复用其预构建自包含 bundle（98928 字节，SHA-256 `e3579493…7742`），未修改任何字节，也未从源码树重建；bundle 内联的 onml/json5/bit-field/logidrom/tspan 未逐一完成传递依赖许可审查。逐项哈希见 [`wavedrom-attribution.json`](../third_party/wavedrom-attribution.json)，边界与排除项见 [`WAVEDROM_NOTICE.md`](../core/integrations/WAVEDROM_NOTICE.md)。

## 外部结果导入

来源下拉框可选 CircuitVision SPICE、HCD JSON 或 tscircuit Circuit JSON，点击“导入外部结果”选择文件，复核候选与issues，再由真实统一门禁决定接受或明确应用为未验证草稿；应用后可编辑和撤销。接口 `POST /api/import/external` 接收 `{source,content,name}`，source 为 `circuitvision_spice`、`hcd`、`tscircuit`，content为UTF-8原文。

目前支持信息完整的电阻、电容、电感和明确电压的直流电源。未知数值、电压、IC引脚或未支持端口不补默认值，不静默删件；无法完整转换时HTTP422整份拒绝，`circuit=null`。形状错误返回400，成功返回200 `needs_review`，初始accepted/electrical_validated均false。适配接口只读格式，未运行模型或仿真；`/api/validate`负责后续电气状态。

旧外部适配单测15/15、HTTP3/3、fixture浏览器17/17、真实服务浏览器2/2以及真实eval输出84条记录的适用门禁均为各自历史证据，分母独立。见历史验收（本地证据）、案例门禁（本地证据）、历史浏览器（本地证据）。
