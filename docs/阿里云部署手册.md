# 智绘电路 CircuitTutor · 阿里云部署手册

> **适用场景**：在**他人的阿里云账号**（ECS 服务器）上部署本项目，且该服务器上已运行着**别人的项目，不可改动**。
>
> **核心原则**：独立目录 · 独立端口 · 独立进程 —— 只增加，不修改。

---

## 实测验证过的部署路径（2026-09-10 真机跑通）

以下路径**已在阿里云 ECS（Alibaba Cloud Linux 3.2104，2核2G）上完整验证**，
含 Python 3.11 安装、网页终端上传、公网访问、真实 LLM 生成全链路：

```bash
# 1) 侦察（只读，务必先做）——记下所有已占端口，一个都别用
sudo ss -lntp

# 2) 建自己的目录
sudo mkdir -p /srv/zhihui && sudo chown -R $USER:$USER /srv/zhihui

# 3) 查 Python 版本（Alibaba Cloud Linux 3.2104 自带 3.6.8，不够）
python3 --version
# 低于 3.10 就装 3.11（实测 dnf 源里有，一次成功）
sudo dnf install -y python3.11 && python3.11 --version

# 4) 上传压缩包后解压（--strip-components=1 剥掉包内 zhihui/ 顶层目录）
sudo tar -xzf /root/zhihui.tar.gz -C /srv/zhihui --strip-components=1

# 5) 启动：只设 PORT，config.py 会自动绑定 0.0.0.0
cd /srv/zhihui && PORT=18080 nohup python3.11 -u -B server.py > server.log 2>&1 &
echo $! > server.pid          # 记下 PID，将来只 kill 这个

# 6) 本机验证
curl -m 5 -si http://127.0.0.1:18080/ | head -4     # 期望 HTTP/1.1 200 OK

# 7) 阿里云控制台 → 安全组 → 入方向 → 手动添加：
#    自定义 TCP | 18080/18080 | 0.0.0.0/0     （只新增，不动已有规则）
```

### 真机踩坑记录（都已在手册正文给出规避方法）

| 坑 | 现象 | 规避 |
|---|---|---|
| **自带 Python 版本过低** | Alibaba Cloud Linux 3.2104 自带 **3.6.8**，项目需 ≥3.10 | `sudo dnf install -y python3.11`（实测源里有） |
| **网页终端不传文件夹** | Workbench 文件面板只支持单文件 | 本地打 `tar.gz` 单包上传（见 `deploy/打包上传.bat`） |
| **多安全组并存** | 实例可能绑多个安全组，需在生效的那个里放行 | `curl -s http://100.100.100.200/latest/meta-data/security-groups` 查询 |
| **服务器内访问公网 IP 不通** | `curl http://<公网IP>:18080/` 空输出/超时，但本机 `127.0.0.1` 正常 | **这是云环境 NAT 回环特性，不代表外网访问不了**——必须从**自己电脑的浏览器**验证 |
| **`curl` 无限卡住** | 不加超时会一直等 | 始终加 `-m 5` 限制超时 |
| **日志里刷异常堆栈** | 非法 HTTP 方法（HEAD/OPTIONS）触发 `TypeError: argument of type 'HTTPStatus' is not iterable` | 已在 `server.py` 修复（`log_message` 统一转字符串），并有测试断言锁定 |

### 日常运维（更新代码）

本地重新打包上传后，在服务器执行：

```bash
bash /srv/zhihui/deploy/update.sh                # 停旧服务→备份→覆盖→回归→重启→自检
bash /srv/zhihui/deploy/update.sh --no-verify    # 跳过回归（更快）
```

配套本地脚本：`deploy/打包上传.bat`（一键打干净的 tar.gz 到桌面）。

**注意**：`nohup` 启动的服务**服务器重启后不会自动恢复**。需要开机自启请配 systemd
（服务名建议 `zhihui`，避免与已有服务名冲突）：

```bash
sudo tee /etc/systemd/system/zhihui.service >/dev/null <<'EOF'
[Unit]
Description=ZhiHui CircuitTutor
After=network.target
[Service]
Type=simple
WorkingDirectory=/srv/zhihui
Environment=PORT=18080
ExecStart=/usr/bin/python3.11 -u -B /srv/zhihui/server.py
Restart=on-failure
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now zhihui
# daemon-reload 只重载 unit 定义，不会重启别人的服务
```

## 〇、部署前必读：三条红线

| 红线 | 具体含义 |
|---|---|
| **不碰别人的文件** | 只在你自己新建的目录里放代码，不修改、不删除、不移动任何已有文件 |
| **不碰别人的进程** | 只启动、只停止自己启动的进程；绝不 `kill` 任何不是你起的进程 |
| **不碰别人的端口** | 只使用侦察后确认空闲的端口；绝不占用 80/443 或别人已监听的端口 |

本项目**全部代码路径基于 `__file__` 解析**（`server.py:52`、`core/templates.py:13`、`kicad/sch_writer.py:467`），
全项目**没有任何 `os.chdir` / `getcwd` 调用**——这意味着把它放在任意目录、从任意位置启动都不会误读别人的文件。

登录 ECS 后，先执行这三条命令。**这一步全是只读的，不会改动任何东西。**

```bash

# 若 ss 不可用，用： sudo netstat -lntp

# 2) 现在跑着哪些进程？—— 哪些不是你的？
ps aux --sort=-%mem | head -20
```

**判读要点**：

- `ss` 输出里出现的端口，**全部视为别人的，禁止使用**
- 输出中 `LISTEN` 状态的 80 / 443 通常是 nginx 或别人的 Web 服务
- 记下别人的项目目录名，**你的新目录不要放在它里面**（不要嵌套）

## 四、选择端口（唯一需要小心的地方）

### 4.1 挑一个空闲端口

推荐在 **10000~60000** 区间选，避开常见服务端口：

```bash
CAND=18080
ss -lntp | grep -q ":$CAND " && echo "$CAND 已被占用，换一个" || echo "$CAND 可用"
```

确认「可用」后就用它。若 18080 被占，依次试 18081、28080、38765……

### 4.2 本项目端口优先级（已内建于 `core/config.py` L95-107）

| 环境变量设置 | 实际绑定 |
|---|---|
| 什么都不设 | `127.0.0.1:8765`（仅本机，外网访问不到） |
| 只设 `PORT` | `0.0.0.0:PORT`（**推荐**，无需改代码） |
| 设 `LSQC_HOST` + `LSQC_PORT` | 按显式值走（优先级最高） |

> **注意**：`LSQC_HOST`/`LSQC_PORT` 只要设了任一，`PORT` 回退就失效。两者选其一，不要混用。

### 4.3 阿里云安全组放行（必须做，否则外网访问不到）

登录**阿里云控制台** → ECS 实例 → **安全组** → 配置规则 → **入方向** → 手动添加：

| 项 | 值 |
|---|---|
| 协议类型 | 自定义 TCP |
| 端口范围 | `18080/18080`（换成你选的端口） |
| 授权对象 | `0.0.0.0/0`（或你自己的 IP，更安全） |
| 描述 | `zhihui-circuit` |

> ⚠️ **只加这一条规则，不要改动、不要删除安全组里任何已有规则**——那些可能是别人项目正在用的。

## 五、启动服务（不干扰别人的进程）

### 方式 A：nohup 快速启动（最简单）

```bash
cd /srv/zhihui
PORT=18080 nohup python3 -B server.py > /srv/zhihui/server.log 2>&1 &
echo $! | sudo tee /srv/zhihui/server.pid
```

**关键一步**：`echo $! > server.pid` 记下自己的进程号。将来要停止时**只 kill 这个 PID**：

```bash
sudo kill $(cat /srv/zhihui/server.pid)
```

这样绝不会误杀别人的进程。

### 方式 B：systemd 托管（推荐，开机自启、崩溃重拉）

创建专用 service 文件（**文件名带前缀，绝不会覆盖别人的服务**）：

```bash
sudo tee /etc/systemd/system/zhihui.service > /dev/null <<'EOF'
[Unit]
Description=ZhiHui CircuitTutor (AI circuit sketch demo)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/srv/zhihui
Environment=PORT=18080
ExecStart=/usr/bin/python3 -B /srv/zhihui/server.py
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF
```

启用并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zhihui
sudo systemctl status zhihui
```

> **安全说明**：`daemon-reload` 只重新加载 unit 定义，**不会重启或影响别人的任何服务**。
> 你的服务名是 `zhihui`，与别人的服务名不冲突。停止时用 `sudo systemctl stop zhihui`，只停自己。

**确认 `ExecStart` 里的 python3 路径**：

```bash
which python3    # 把输出填进 ExecStart，常见 /usr/bin/python3 或 /usr/local/bin/python3
```

## 六、API Key 的处理（重要）

### 强烈建议：不要把 Key 写进服务器环境变量

**推荐做法**：让访问者**在网页上自己填 Key**。

本项目原生支持这个机制（`server.py` 的 `/api/llm_config` 端点，**POST** 方法）：

- Key 只存**浏览器 localStorage** + **服务端内存表**（`server.py:165` TTL = 2 小时，过期销毁）
- **不落盘**、**不进 URL**（Key 用内存里的 `cfg_id` 间接引用）、**不打日志**
- 谁用谁付，你不需要为线上环境配任何 Key

打开网页后，界面上有填 Key 的入口，填完即可触发真实 LLM 生成。
不填的话，前端会自动回落到内置模板兜底，演示流程不受影响。

### 何时才需要配 env 变量

若你想让**所有访问者共享你自己的 Key**（比如课堂演示），才需要：

```bash
# 在 systemd service 里加一行（或在 nohup 前 export）
Environment=DEEPSEEK_API_KEY=sk-xxxxxxxx
```

但请注意：这会让服务器上的该 Key 对**所有访问者**可用，且有落盘痕迹。**在别人的服务器上，更推荐网页填 Key 的方式。**

### 不配 Key 会怎样？

**完全不影响演示**。项目自动走**内置模板兜底**：9 套内置电路（555 闪烁灯、LED 限流等），
SSE 流式输出、SVG 渲染、交互编辑全部正常工作。启动时会打印提示：

```
API Key：未配置，走内置模板兜底（可正常演示 SSE + 渲染）
```

## 十、FAQ

**Q：会不会影响别人正在运行的项目？**
A：不会。你只做了三件事：新建一个目录、启动一个自己的进程、占用一个空闲端口。文件、进程、端口三个维度全部隔离。唯一需要人工确认的是端口——所以第一步必须先 `ss -lntp` 侦察。

**Q：阿里云安全组能改吗？**
A：可以**新增**一条规则，但**不要修改或删除已有的规则**。

**Q：需要 sudo 吗？**
A：建目录、装 systemd service 需要；如果放在自己的 home 目录（如 `~/zhihui`）并用高位端口（>1024），可以完全不用 sudo。

**Q：别人的服务器上，我怎么知道自己有没有踩到别人？**
A：部署前后各跑一次 `sudo ss -lntp`，对比输出——如果只有你新增的端口多了，其他一模一样，就说明完全没干扰。

**Q：项目会不会自动向外发请求？**
A：只有在**配置了 Key 并触发了生成**时才会调用 DeepSeek API。无 Key 时全程离线，走模板兜底。
